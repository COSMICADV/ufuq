## What is complete

### Foundation packages (unchanged in this revision except where noted)

- pnpm workspace and Turborepo task graph
- TypeScript configuration, shared and strict
- ESLint with decimal-safety and module-boundary rules, plus Prettier
- `@ufuq/money` — fixed-precision decimal, `Money`, `Quantity`, rounding policies
- `@ufuq/i18n` — locales, direction, message catalogues, locale-aware formatters.
  **Changed:** an `error.*` namespace was added so the API's error envelope is
  bilingual from the same catalogue as every other string (DOCUMENT 27 RULE 25).
- `@ufuq/config` — fail-fast environment validation with secret redaction
- Docker Compose: PostgreSQL, Redis, MinIO with a private bucket

### Applications

**`apps/api` — NestJS**

- Bootstrap validates the environment through `@ufuq/config` before constructing
  anything, and prints no secret when it fails (DOCUMENT 20 §8, §11).
- Global prefix `/api/v1`, fixed for the lifetime of V1 (DOCUMENT 08 §7).
- The DOCUMENT 08 §2 envelopes: `{ data, meta }` for success,
  `{ error: { code, message_ar, message_en, fields? } }` for failure.
- One exception filter is the only place an error becomes a response. A 500
  logs its cause server-side and tells the client nothing but the code
  (DOCUMENT 08 §3).
- A route that matches nothing answers `404 NOT_FOUND` in the documented shape,
  not the framework's default HTML page.
- `Accept-Language` negotiation delegated to `@ufuq/i18n`; default `ar`
  (DOCUMENT 08 §1).
- Credentialed CORS restricted to `WEB_ORIGIN` (OD-02).
- `GET /api/v1/health` — the DOCUMENT 25 Phase 1 health check. It reports only
  what the process can answer without a dependency: that it is up, which build
  it is, and which environment it believes it is in. It is unauthenticated on
  purpose: a liveness probe that needs a session cannot report that sessions are
  broken.
- Dependencies are injected by explicit token rather than by emitted parameter
  metadata, which keeps `verbatimModuleSyntax` on and makes each injection
  readable at its call site.

**`apps/web` — Next.js (App Router)**

- Every route lives under `/{locale}`. The root layout reads that segment and
  sets `lang` and `dir` from `@ufuq/i18n`'s `documentAttributes`. Nothing below
  the root decides its own direction (DOCUMENT 10 §9, DOCUMENT 27 RULE 24).
- Both locales are prerendered as static HTML. Neither is a runtime fallback for
  the other.
- A request without a locale prefix is redirected to the language
  `Accept-Language` asks for, falling back to Arabic.
- The language switch renders plain anchors, so it works with JavaScript
  disabled (DOCUMENT 23) and forces the document reload that a change of `dir`
  requires.
- The stylesheet contains layout primitives only, all logical properties. There
  are no colour, type or spacing tokens: those are DOCUMENT 10 and they are
  built in Phase 2 (DOCUMENT 27 RULES 21–23).

**`apps/mobile` — Expo + React Native**

- The shell reads both catalogues and switches language and direction. React
  Native has no document to carry `dir`, so direction is applied as a style —
  but it is still derived from the locale by `@ufuq/i18n`, in one place.
- Metro is configured for the pnpm workspace; without that it cannot resolve
  `@ufuq/i18n`.
- `pnpm --filter @ufuq/mobile run bundle:check` bundles the application through
  Metro and is run in CI. There is no `build` task: a native binary is produced
  by the release pipeline in Phase 18, and a build script that produced nothing
  would be a placeholder (DOCUMENT 27 RULE 26). The check skips Hermes bytecode,
  which is a release concern, so it runs on any CPU architecture.

### Verification

`pnpm verify` now covers the whole exit criterion. It starts the built API and
the built web application on free ports and asserts:

- `GET /api/v1/health` returns `200` with `data.status === "ok"` in Arabic and
  in English, chosen by `Accept-Language`
- an unknown path returns `404 NOT_FOUND` with both messages present
- no secret from the environment appears in any response body
- `/ar` serves `<html lang="ar" dir="rtl">` and `/en` serves
  `<html lang="en" dir="ltr">`
- each page carries a server-rendered link to the other language
- `/` redirects to `/ar`, `/en`, or `/ar` for an unsupported language

No infrastructure is required: nothing in Phase 1 opens a database, a queue, or
a bucket.

CI runs format, lint, typecheck, test, build, and then `verify` — in that order,
because `verify` starts the built output. A second job bundles the Expo
application.

### One foundation defect found and fixed

`pnpm build` could silently emit nothing. Each package's TypeScript build info
was written to the package root, and the `typecheck` script — `tsc --noEmit`
against the same `tsconfig.json` — wrote it too. After a `pnpm clean`, or simply
after `pnpm typecheck`, the next `pnpm build` believed its output was current and
produced no `dist` at all. `pnpm verify` then reported a package as "not built",
which is true but points at the wrong cause.

Two changes, both behaviour-preserving (DOCUMENT 27 RULE 1):

- every emitting package writes its build info to `dist/tsconfig.tsbuildinfo`,
  so the record and the output it describes are deleted together
- `typecheck` runs with `--incremental false`, so a no-emit check can never
  convince a later build that there is nothing to do

`pnpm clean` now also removes application output and any stray build info.

## Deviations from DOCUMENT 25's Phase 1 list, and why

DOCUMENT 25 lists "database connection, migration tooling" among Phase 1's
contents. They are **not** in this phase, by explicit instruction: Prisma begins
in the database phase. Everything else on that list is present. This is recorded
here rather than left implicit, per DOCUMENT 27 RULE 1.

Server-side input validation (DOCUMENT 08 §5, DOCUMENT 27 RULE 28) has no
subject yet: no Phase 1 endpoint accepts input. The validation pipe and its
schema arrive with the first endpoint that takes a body, in Phase 3. It is not
stubbed here, because a validation layer with nothing to validate cannot be
tested and would be trusted anyway.
